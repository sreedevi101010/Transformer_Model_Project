# IndicTrans2 LoRA Fine-tuning: Malayalam ↔ Hindi

This project fine-tunes [IndicTrans2](https://github.com/AI4Bharat/IndicTrans2) (`ai4bharat/indictrans2-indic-indic-dist-320M`) using LoRA adapters for **Malayalam ↔ Hindi** translation. The training dataset is synthetically generated through an optimized retrieval pipeline — and the fine-tuned model is compared against the baseline (zero-shot) IndicTrans2 to measure the impact of domain-specific fine-tuning.

## Dataset Generation

The training dataset is built from raw (unpaired) Malayalam and Hindi sentence corpora using a multi-stage retrieval and quality-filtering pipeline.

### Pipeline Steps

**1. Embedding** — All Hindi sentences are embedded using [LaBSE](https://huggingface.co/sentence-transformers/LaBSE) and indexed with FAISS (both cosine/IP and L2 indices).

**2. Retrieval** — For each Malayalam sentence, the top-K Hindi candidates are retrieved (`search_k=100` default).

**3. Combined Scoring** — Each candidate is scored as:
```
score = cosine_weight × cosine_sim + l2_weight × (1 − l2_dist)
```

**4. Adaptive Scoring** — Z-score normalization is applied locally within each candidate set. Outliers below `z_threshold` are filtered. Final score:
```
adaptive_score = base_weight × score + z_weight × z_score_normalized
```

**5. Density Filtering** — Candidates in sparse regions of embedding space receive a bonus; candidates in crowded regions receive a penalty.

**6. COMET-KIWI Quality Gating** — The top-N candidates after filtering are scored by `Unbabel/wmt22-cometkiwi-da`. Only pairs with COMET score ≥ `comet_threshold` are kept.

### Parameter Experiments

Because the retrieval pipeline has many tunable parameters, a full grid search is supported via:

```bash
# Step 1: Generate parameter grids
python generate_parameter_datasets_simple.py
# → creates parameter_experiments/parameters_minimal.csv
#             parameter_experiments/parameters_focused.csv
#             parameter_experiments/parameters_baseline.csv

# Step 2: Run baseline experiments first
python run_parameter_experiments.py \
    --params parameter_experiments/parameters_baseline.csv \
    --results results_baseline.csv

# Step 3: Run full grid search
python run_parameter_experiments.py \
    --params parameter_experiments/parameters_minimal.csv \
    --results results_minimal.csv
```

The runner tracks the best experiment in real-time by **Weighted Pre-COMET Rank Score**:

| Rank | Weight |
|------|--------|
| 1    | 1.0    |
| 2    | 0.7    |
| 3    | 0.5    |
| 4    | 0.3    |
| 5+   | 0.1    |
| fail | 0.0    |

The best configuration's output pairs are saved to `final_best_pairs.csv` and used as `dataset_train.csv` for fine-tuning.

**Key parameters explored:**

| Parameter | Description |
|-----------|-------------|
| `cosine_weight` / `l2_weight` | Combined retrieval score blend |
| `base_weight` / `z_weight` | Adaptive scoring blend |
| `z_threshold` | Z-score cutoff for filtering weak candidates |
| `sparse_bonus` / `crowded_penalty` | Density-based score adjustment |
| `sparse_threshold` / `crowded_threshold` | Density region boundaries |
| `comet_threshold` | Minimum COMET-KIWI score to keep a pair |
| `top_after_filtering` | Top-N candidates sent to COMET |

## Fine-tuning

### Model

- **Base model:** `ai4bharat/indictrans2-indic-indic-dist-320M`
- **Method:** LoRA (PEFT) — separate direction-specific adapters for ml→hi and hi→ml
- **LoRA targets:** `q_proj`, `k_proj`, `v_proj`, `out_proj`, `fc1`, `fc2` (rank=16, alpha=32)

### Training Configuration

| Hyperparameter | Value |
|----------------|-------|
| Epochs | 3 |
| Batch size | 16 (effective 32 with grad accumulation) |
| Learning rate | 2e-4 |
| LR schedule | Cosine with warmup (3%) |
| Weight decay | 0.01 |
| Label smoothing | 0.1 |
| Max grad norm | 1.0 |
| Precision | BF16 (with gradient checkpointing) |
| Eval metric | chrF++ (sacrebleu) |
| Early stopping | Patience = 3 eval ticks |
| Eval frequency | Every 500 steps |

### Data Split

A stratified 98/1/1 train/val/test split is used, bucketed by Hindi token length to maintain length distribution balance.

### Running Fine-tuning

```bash
# Both directions (default)
python IndicTrans2_LoRA_fine.py --data dataset_train.csv

# Single direction
python IndicTrans2_LoRA_fine.py --data dataset_train.csv --only ml2hi
python IndicTrans2_LoRA_fine.py --data dataset_train.csv --only hi2ml
```

**Input CSV format:**

```
malayalam,hindi
നിങ്ങൾ എങ്ങനെ ഉണ്ട്?,आप कैसे हैं?
...
```

## Evaluation

Both the fine-tuned model and the baseline (zero-shot IndicTrans2) are evaluated on the held-out test set using:

- **chrF++** — character n-gram F-score with word-order penalty (primary metric)
- **BLEU** — n-gram precision baseline

Fine-tuned test metrics are written automatically to `outputs/ml2hi/test_metrics.txt` and `outputs/hi2ml/test_metrics.txt` at the end of training. To evaluate the zero-shot baseline, run inference with the unmodified `ai4bharat/indictrans2-indic-indic-dist-320M` on the same `outputs/test.csv`.
